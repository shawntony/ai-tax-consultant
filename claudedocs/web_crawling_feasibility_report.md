**작성일**: 2025-10-18
**작성자**: AI Tax Consultant Development Team
**조사 시간**: 6h
**조사 목적**: 국세청 홈페이지 세율 정보 웹 크롤링의 법적·기술적 가능성 평가

---

## 📋 Executive Summary

### 조사 결과 요약
국세청 홈페이지 웹 크롤링은 **기술적으로는 가능하나, 법적으로는 제약이 많아 권장하지 않음**.

### 주요 발견사항
1. ⚠️ **국세청 저작권 정책**: 사전 협의 및 허가 필수 (상업적 이용 금지)
2. ❌ **공공누리 미적용**: 국세청은 공공저작물 자유이용 허락 제도 미적용
3. ✅ **대법원 판례**: 공개된 데이터 크롤링은 조건부 합법 (대법원 2021도1533)
4. ⚠️ **기술적 제약**: robots.txt 확인 필요, Rate Limiting 준수 필수
5. ⚠️ **유지보수 부담**: 웹사이트 구조 변경 시 크롤링 로직 수정 필요

### 최종 권장사항
**❌ 웹 크롤링 방식은 채택하지 않는 것을 권장**
- **대안 1**: 수동 업데이트 (연 1-2회, 가장 안전)
- **대안 2**: 변경 감지 알림 시스템 (M2.1.10.3에서 설계)
- **대안 3**: 정보공개청구 제도 활용

## 🔍 1. 법적 검토

### 1.1 국세청 저작권 정책

**공식 정책 URL**: https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?mi=6791&cntntsId=8169

#### 주요 내용

**소유권**:
```
국세청 홈페이지를 통하여 제공되는 모든 콘텐츠는
국세청에 저작권이 있습니다.
```

**사용 제한**:
```
개인 또는 법인이 국세청 홈페이지의 콘텐츠를
링크·인용·복제·배포하고자 하는 경우에는
사전에 국세청과 협의하고 허가를 득해야 합니다.
```

**필수 조건**:
1. **출처 표시**: 국세청 홈페이지에서 취득한 것임을 명확히 표시
2. **저작권 명시**: 저작권 및 출처를 명시하여 이용자 혼동 방지
3. **비상업적 이용**: 어떠한 경우에도 상업적 목적으로 사용 금지

**예외 사항**:
- 디자인 이미지: 별도 저작권법 규정 적용
- 게시판 사용자 콘텐츠: 정책 적용 제외

#### 법적 평가

| 항목 | 평가 | 설명 |
|------|------|------|
| **크롤링 허용 여부** | ⚠️ **조건부** | 사전 협의 및 허가 필요 |
| **상업적 이용** | ❌ **불가** | AI Tax Consultant는 상업적 목적 |
| **출처 표시** | ✅ **필수** | 준수 가능 |
| **기술적 제한** | ⚠️ **확인 필요** | robots.txt 확인 필요 |

**결론**: 국세청 저작권 정책상 **사전 허가 없는 크롤링은 위험**

### 1.2 공공저작물 자유이용 허락 (공공누리/KOGL)

#### 공공누리 제도 개요

**법적 근거**: 저작권법 제24조의2 (공공저작물의 자유이용)

**제도 목적**:
```
국가나 지방자치단체 등이 업무상 작성하여
공표한 저작물이나 계약에 따라 저작재산권의
전부를 보유한 저작물에 대해 국민이 자유롭게
이용할 수 있도록 허락하는 제도
```

**4가지 유형**:

| 유형 | 조건 | 허용 범위 |
|------|------|----------|
| **제1유형** | 출처표시 | 상업적 이용 ✅, 변형 ✅ |
| **제2유형** | 출처표시 + 상업적이용금지 | 상업적 이용 ❌, 변형 ✅ |
| **제3유형** | 출처표시 + 변경금지 | 상업적 이용 ✅, 변형 ❌ |
| **제4유형** | 출처표시 + 상업적이용금지 + 변경금지 | 상업적 이용 ❌, 변형 ❌ |

#### 국세청의 공공누리 적용 여부

**조사 결과**: ❌ **국세청 홈페이지는 공공누리 표시가 없음**

**타 공공기관 사례**:
- 행정안전부: 공공누리 제1유형 적용
- 기획재정부: 공공누리 제1유형 적용
- 법제처: 공공누리 제1유형 적용

**국세청의 경우**:
- 공공누리 표시 없음
- 별도 저작권 정책 적용 (제한적)
- 사전 허가 요구

**법적 평가**:

공공누리 미적용으로 인해 **일반 저작물과 동일하게 취급**되어야 하며, 저작권법상 허용되는 범위를 초과하는 이용은 저작권 침해에 해당할 수 있음.

### 1.3 웹 크롤링 관련 판례 분석

#### 대법원 2021도1533 판결 (2022.5.12. 선고)

**사건 개요**:
- 경쟁사 모바일 앱의 영업 정보를 크롤링한 사건
- 1심: 유죄 (정보통신망법, 저작권법, 업무방해)
- 항소심/대법원: **무죄 확정**

**주요 판시 사항**:

##### 1) 저작권법 (데이터베이스 제작자 권리)

**법률 조항**: 저작권법 제93조

```
데이터베이스제작자는 그 데이터베이스의 전부
또는 상당한 부분을 복제·배포·방송 또는
전송할 권리를 가진다.
```

**대법원 판단 기준**:

```
개별 소재의 복제라도 다음의 경우
"상당한 부분의 복제"로 간주:

1. 반복적 또는 체계적인 복제
2. 데이터베이스의 통상적 이용과 충돌
3. 제작자의 이익을 부당하게 해치는 경우
```

**판례 적용**:
- 단순히 여러 번 복제했다는 사실만으로는 부족
- 데이터베이스의 **핵심적이고 상당한 부분**을 무단으로 가져가는 경우에만 위법

**국세청 세율 정보 적용**:
- ✅ 세율표는 데이터베이스의 일부분
- ⚠️ 반복적·체계적 수집 시 문제 가능성
- ⚠️ 상업적 이용 시 "이익 침해" 주장 가능

##### 2) 정보통신망법 (정보통신망 침입)

**법률 조항**: 정보통신망법 제48조

```
누구든지 정당한 접근권한 없이 또는
허용된 접근권한을 넘어서 정보통신망에
침입하여서는 아니 된다.
```

**대법원 판단 기준**:

```
접근권한 제한 여부 판단 시 고려사항:
1. 기술적 보호조치 (로그인, 인증 등)
2. 이용약관의 명시적 금지 조항
3. 기타 객관적으로 드러난 사정
```

**판례 적용**:
- 단순히 약관에 금지 조항만 있다고 해서 "정당한 접근권한 없음"으로 보지 않음
- **실질적인 기술적 보호조치**가 있어야 함

**국세청 홈페이지 적용**:
- ✅ 세율 정보는 공개된 페이지
- ✅ 로그인이나 인증 없이 접근 가능
- ⚠️ 이용약관상 제한은 있음
- **평가**: 정보통신망 침입죄는 성립하기 어려움

##### 3) 컴퓨터등장애업무방해죄

**법률 조항**: 형법 제314조 제2항

```
컴퓨터 등 정보처리장치 또는
전자기록등 특수매체기록을 손괴하거나
정보처리장치에 허위의 정보 또는
부정한 명령을 입력하거나 기타 방법으로
정보처리에 장애를 발생하게 하여
사람의 업무를 방해한 자
```

**대법원 판단 기준**:

```
업무방해죄 성립 요건:
1. 정보처리에 장애 발생
2. 사람의 업무 방해
3. 고의성
```

**판례 적용**:
- 일반적인 웹 접속과 유사한 수준의 크롤링은 "장애 발생"으로 보기 어려움
- 서버에 과도한 부하를 주는 경우에만 문제

**국세청 홈페이지 적용**:
- ✅ Rate Limiting 준수 시 장애 발생 가능성 낮음
- ⚠️ 과도한 요청 시 업무방해 가능성

---

#### 판례 종합 평가

| 법률 | 위반 가능성 | 조건 | 국세청 적용 |
|------|------------|------|------------|
| **저작권법** | ⚠️ 중간 | 상당한 부분 복제 시 | 세율표만 추출 시 낮음 |
| **정보통신망법** | ✅ 낮음 | 기술적 보호조치 우회 시 | 공개 페이지라 낮음 |
| **업무방해** | ⚠️ 중간 | 서버 과부하 발생 시 | Rate Limiting 준수 시 낮음 |

**종합 결론**:
- 공개된 세율 정보를 **적절한 방법**으로 크롤링하는 것은 형사처벌 가능성이 낮음
- 다만, **국세청 저작권 정책**상 사전 허가가 요구되므로 **민사적 책임**은 별도
- **상업적 이용**은 국세청 정책상 명시적으로 금지

### 1.4 개인정보보호법 검토

#### 법적 근거

**개인정보보호법 제15조 (개인정보의 수집·이용)**

```
개인정보처리자는 다음 각 호의 어느 하나에
해당하는 경우에는 개인정보를 수집할 수 있으며
그 수집 목적의 범위에서 이용할 수 있다.

1. 정보주체의 동의를 받은 경우
```

#### 국세청 세율 정보 적용

**조사 결과**: ✅ **개인정보 미포함**

**세율 정보의 특성**:
- 상속세 세율표: 과세표준 구간과 세율 (개인정보 없음)
- 증여세 세율표: 과세표준 구간과 세율 (개인정보 없음)
- 양도소득세 세율표: 과세표준 구간과 세율 (개인정보 없음)
- 공제 정보: 법정 공제 금액 (개인정보 없음)

**평가**: ✅ **개인정보보호법 위반 위험 없음**

### 1.5 법적 리스크 종합 평가

#### 리스크 매트릭스

| 위험 요소 | 발생 가능성 | 영향도 | 리스크 레벨 | 대응 방안 |
|----------|------------|--------|------------|----------|
| **저작권 침해** | 중간 | 높음 | 🟡 중간 | 사전 허가 취득 |
| **정보통신망 침입** | 낮음 | 높음 | 🟢 낮음 | 공개 페이지만 접근 |
| **업무방해** | 낮음 | 높음 | 🟢 낮음 | Rate Limiting 준수 |
| **상업적 이용 금지 위반** | 높음 | 중간 | 🔴 높음 | 사전 허가 취득 |
| **약관 위반** | 높음 | 낮음 | 🟡 중간 | 국세청과 협의 |

#### 형사적 책임 vs 민사적 책임

**형사적 책임**: 🟢 **낮음**
- 대법원 판례상 공개된 정보의 크롤링은 형사처벌 가능성 낮음
- Rate Limiting 준수 시 업무방해 위험 거의 없음

**민사적 책임**: 🟡 **중간~높음**
- 국세청 저작권 정책 위반으로 인한 손해배상 청구 가능
- 상업적 이용 금지 조항 위반 시 법적 분쟁 가능성

**평판 리스크**: 🔴 **높음**
- 공공기관 약관 무시로 인한 부정적 이미지
- "세금 자문 앱이 국세청 약관 위반"이라는 모순

### 1.6 법적 대응 방안

#### 방안 1: 사전 허가 취득 (권장)

**절차**:
1. 국세청 저작권 담당 부서에 공문 발송
2. 크롤링 목적, 방법, 범위 설명
3. 상업적 이용에 대한 협의
4. 허가 취득 후 크롤링 시작

**장점**:
- ✅ 법적 리스크 완전 해소
- ✅ 국세청과의 협력 관계 구축
- ✅ 안정적인 데이터 수집

**단점**:
- ❌ 허가 취득 시간 소요 (수주~수개월)
- ❌ 거부 가능성 (상업적 이용 금지 조항)
- ❌ 허가 조건 제약 가능성

**소요 기간**: 1~3개월

---

#### 방안 2: 비상업적 이용 주장 (부분적)

**논리**:
```
AI Tax Consultant는 세금 계산 보조 도구로,
국세청 세율 정보를 그대로 제공하는 것이 아니라
계산 로직에 활용하는 것이므로
"공정 이용" 범위에 해당한다고 주장
```

**법적 근거**: 저작권법 제28조 (공정 이용)

```
공표된 저작물은 보도·비평·교육·연구 등을
위하여는 정당한 범위 안에서
공정한 관행에 합치되게 이용할 수 있다.
```

**평가**:
- ⚠️ "교육·연구" 목적으로 주장 가능하나 약함
- ❌ AI Tax Consultant는 사실상 상업적 서비스
- ❌ 국세청 정책상 명시적으로 상업적 이용 금지

**위험도**: 🔴 **높음** (법적 분쟁 가능성)

---

#### 방안 3: 정보공개청구 제도 활용 (대안)

**법적 근거**: 공공기관의 정보공개에 관한 법률

**절차**:
1. 정보공개포털 (www.open.go.kr) 접속
2. 국세청에 "세율표 데이터" 정보공개 청구
3. 구조화된 데이터 형식 (JSON, CSV 등) 요청
4. 승인 후 데이터 취득

**장점**:
- ✅ 합법적인 데이터 취득 방법
- ✅ 국세청 공식 데이터
- ✅ 법적 리스크 없음

**단점**:
- ❌ 처리 기간 소요 (10~20일)
- ❌ 거부 가능성
- ❌ 데이터 형식 제약

**평가**: ✅ **권장** (합법적 대안)

## 🔧 2. 기술적 검토

### 2.1 robots.txt 분석

#### robots.txt 확인 방법

**URL**: https://www.nts.go.kr/robots.txt

**조사 결과**:
- WebFetch 시도 시 인증 오류 발생
- 직접 URL 접속 필요

#### robots.txt 준수 원칙

**로봇 배제 표준 (Robot Exclusion Standard)**:
```
robots.txt는 권고안이지만,
웹서버 운영자의 의도를 따르는 것이 좋음.

금지된 웹페이지에 빈번하게 접근하는 행위는
웹서버 공격으로 간주될 수 있음.
```

**일반적인 구조**:
```
User-agent: *
Disallow: /admin/
Disallow: /private/
Crawl-delay: 10
```

**국세청 예상 설정**:
- 일반 공개 페이지: 크롤링 허용 가능성 높음
- 세율 정보 페이지: 명시적 금지 가능성 낮음
- Crawl-delay: 설정 가능성 있음

**권장 사항**:
1. robots.txt 직접 확인 필수
2. Disallow 경로 준수
3. Crawl-delay 준수
4. 의문 사항 시 국세청에 문의

#### 2) Rate Limiting (요청 속도 제한)

**목적**: 서버 부하 방지 및 DDoS 공격 오인 방지

**권장 설정**:
```python
import time
import random

def fetch_with_rate_limit(url):
    # 요청 간 1~3초 랜덤 대기
    time.sleep(random.uniform(1, 3))

    response = requests.get(url, headers=headers)

    # 429 (Too Many Requests) 응답 시 대기
    if response.status_code == 429:
        retry_after = int(response.headers.get('Retry-After', 60))
        time.sleep(retry_after)
        return fetch_with_rate_limit(url)

    return response
```

**권장 기준**:
- **최소 대기 시간**: 1초
- **평균 대기 시간**: 2~3초
- **동시 연결 수**: 1개
- **시간당 요청 수**: 최대 1000건

**대법원 판례 관점**:
- 적절한 Rate Limiting은 "업무방해" 위험 감소
- 서버에 과도한 부하를 주지 않는 것이 중요

#### 3) 에러 핸들링

**목적**: 안정적인 크롤링 및 서버 보호

**권장 구현**:
```python
def crawl_tax_rate_page(url, max_retries=3):
    for attempt in range(max_retries):
        try:
            response = fetch_with_rate_limit(url)

            if response.status_code == 200:
                return parse_html(response.text)
            elif response.status_code == 404:
                logger.error(f'Page not found: {url}')
                return None
            elif response.status_code == 403:
                logger.warning(f'Access forbidden: {url}')
                return None
            elif response.status_code == 503:
                # 서비스 일시 중단, 재시도
                time.sleep(60 * (attempt + 1))
                continue

        except requests.exceptions.RequestException as e:
            logger.error(f'Request failed: {e}')
            time.sleep(10 * (attempt + 1))
            continue

    return None
```

**처리해야 할 상황**:
- **200 OK**: 정상 처리
- **403 Forbidden**: 접근 거부 (크롤링 중단)
- **404 Not Found**: 페이지 없음 (URL 확인)
- **429 Too Many Requests**: 요청 과다 (대기 후 재시도)
- **500 Internal Server Error**: 서버 오류 (재시도)
- **503 Service Unavailable**: 서비스 중단 (대기 후 재시도)

#### 5) 데이터 검증

**목적**: 크롤링한 데이터의 정확성 보장

```python
def validate_tax_rates(rates):
    """세율 데이터 검증"""

    # 1. 필수 필드 존재 확인
    for rate in rates:
        assert 'bracket' in rate
        assert 'rate' in rate
        assert 'min_amount' in rate

    # 2. 논리적 일관성 확인
    for i in range(len(rates) - 1):
        # 과세표준이 순차적으로 증가하는지
        assert rates[i]['max_amount'] == rates[i+1]['min_amount']
        # 세율이 누진적으로 증가하는지
        assert rates[i]['rate'] <= rates[i+1]['rate']

    # 3. 예상 범위 확인
    assert len(rates) == 5  # 상속세는 5개 구간
    assert rates[0]['rate'] == 0.10  # 최저세율 10%
    assert rates[-1]['rate'] == 0.50  # 최고세율 50%

    return True
```
